# 安全性: 許可リスト方式

## 問題

Igor の `Execute` は、渡された文字列を「コマンドラインに打ったもの」として何でも実行します（`ExecuteScriptText` を使えば Windows のコマンドラインまで届きます）。
`.h5` に描画命令を入れて、ローダーが `Execute` で実行する設計なので、**人から受け取ったファイルを開くだけで、任意のコマンドが走る**危険があります。

## 対策（不変条件。テストが守っている）

1. **許可リストは `export_igorgraph/eig_allowlist.py` の 1 か所だけ**。ローダー（`make_loader.py` が生成）も、`export_igor` の自己検査も、テストも、ここを使う。パターンを変えたらローダーを再生成する（パターンの指紋が `.ipf` の先頭に入り、`test_loader.py` が古さを検出する）。
2. ローダーは、**全命令を先に検査し、1 つでも外れたら何も読み込まず、何も実行しない**。`Execute` を使うのは 1 か所だけ（`EIG_RunCommand`。`// style-allow: Execute` の印つき）で、実行の直前にもう一度検査する。実行した命令は History に全部出る。
3. パターンは**全文一致**（`^…$`）。使えるキーワードは列挙した形だけ。`;`（命令の連結）は、引用符の中以外では通らない。文字列は `"(?:[^"\\]|\\.)*"` に限る（引用符を抜けられない）。
4. 制御文字・非ASCII・2400 バイト超の命令は無条件に拒否（`Execute` の上限は 2500 バイト）。`font=` は決まったフォント名だけ。
5. `export_igor` は、書き出し時に、生成した全命令が許可リストを通ることを検査する（通らなければ例外）。
6. **緩い正規表現（`.*` など）で許可リストを緩めない**。新しい命令の形を足すときは、(a) 厳密なパターンと、正常・悪意の両方の見本を `eig_allowlist.py` に足す、(b) ローダーを再生成する、(c) `test_loader.py` を通す。
7. 自動実行（`tools/run_igor_round.py`）は、自分で生成した `.h5` だけを開く。

## テスト

- 正常な見本（`GOOD_SAMPLES`）がすべて通り、悪意のある見本（`BAD_SAMPLES`: `ExecuteScriptText`、`;KillWaves/A` の連結、引用符の抜け、改行の差し込み、未知のキー、長すぎる命令、…）がすべて拒否される。
- Igor の中でも `EIG_SelfTest()` が同じ見本で検査する（Igor 8.04 で全部通る）。
- `test_loader.py`: ローダーの正規表現が Python と同じ意味か、ギャラリー全図の命令（約 800 個）が通るか、ローダーが規約チェッカーを通るか。

## 限界（正直に）

- 許可される命令は、グラフを作る・整えるものだけです（ファイル・外部コマンド・任意の式は不可）。それでも次のことは**防げません**:
  - `DoWindow/K <名前>` は、その名前の**既存のウィンドウを確認なしで閉じる**。悪意のあるファイルは、開いている別のグラフを閉じられる（未保存の作業を失いうる）。
  - 重いデータや大量の命令で Igor を遅くすること。
  - 同じ名前の図を読み直すと、データフォルダ `root:<name>` の Wave は上書き（`/O`）される。
- 許可リストの設計の誤りは、ありうる。**脆弱性は、非公開で報告してください**（`SECURITY.md`）。
