# Safety: the allow-list design

## The problem

Igor's `Execute` runs any string as if it were typed on the command line (with `ExecuteScriptText` it can even reach the Windows command line).
The `.h5` carries drawing commands that the loader runs with `Execute`, so **merely opening a file you received could run arbitrary commands**.

## The countermeasures (invariants; enforced by tests)

1. **One allow-list**, in `export_igorgraph/eig_allowlist.py`. The loader (generated by `make_loader.py`), the self-check in `export_igor`, and the tests all use it. After changing a pattern, regenerate the loader (a pattern fingerprint is written at the top of the `.ipf`; `test_loader.py` detects a stale loader).
2. The loader **checks every command first; if any command is rejected, nothing is loaded and nothing is executed**. `Execute` is used in exactly one place (`EIG_RunCommand`, marked `// style-allow: Execute`), and the command is checked again right before it runs. Every executed command is printed to the history.
3. Patterns are **full matches** (`^…$`). Only enumerated keywords are allowed. `;` (command chaining) never passes outside a quoted string. Strings must match `"(?:[^"\\]|\\.)*"` (no escaping out of a quote).
4. Control characters, non-ASCII and commands over 2400 bytes are rejected unconditionally (`Execute` has a 2500-byte limit). `font=` accepts only a fixed list of names.
5. `export_igor` verifies at export time that every generated command passes the allow-list (otherwise it raises).
6. **Never loosen the allow-list with a permissive regex (`.*`).** To add a command form: (a) add a strict pattern plus good *and* malicious samples to `eig_allowlist.py`, (b) regenerate the loader, (c) make `test_loader.py` pass.
7. Automated runs (`tools/run_igor_round.py`) only open `.h5` files that the tool itself generated.

## Tests

- The good samples (`GOOD_SAMPLES`) pass and the malicious ones (`BAD_SAMPLES`: `ExecuteScriptText`, `;KillWaves/A` chaining, quote escapes, embedded newlines, unknown keys, over-long commands, …) are rejected.
- Inside Igor, `EIG_SelfTest()` checks the same samples (all pass on Igor 8.04).
- `test_loader.py` checks that the loader's regexes behave like Python's, that all gallery commands (~800) pass, and that the loader passes the style checker.

## Limits (be honest)

- Allowed commands only create and format graphs (no files, no external commands, no arbitrary expressions). They still can:
  - `DoWindow/K <name>` closes an **existing window with that name without asking** — a malicious file could close another open graph (unsaved work may be lost);
  - slow Igor down with large data or many commands;
  - overwrite the waves in the data folder `root:<name>` (loaded with `/O`) when a figure with the same name is loaded again.
- Allow-list design mistakes are possible. **Please report vulnerabilities privately** (see `SECURITY.md`).
